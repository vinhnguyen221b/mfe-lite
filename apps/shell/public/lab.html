MFE Lite Lab

Two zones · one domain · Vercel Hobby
Sheet 1 · Overview

Two Next.js apps. One domain. Zero dollars.

MFE Lite is the smallest honest demo of Vercel Microfrontends. A shell project is the default app and a blog project is the child zone. Visitors only see mfe-lite-shell.vercel.app; the group mfe-lite decides which project answers each path.

apps/shell/microfrontends.json

The only routing table. It lives in the default app, is read by withMicrofrontends at build time, and defines the group's paths. The default app has no routing: it owns whatever nobody else claims.

{
  "$schema": "https://openapi.vercel.sh/microfrontends.json",
  "applications": {
    "mfe-lite-shell": {
      "packageName": "@mfe-lite/shell",
      "development": {
        "fallback": "mfe-lite-shell.vercel.app",
        "local": 3000
      }
    },
    "mfe-lite-blog": {
      "packageName": "@mfe-lite/blog",
      "routing": [
        { "group": "blog", "paths": ["/blog", "/blog/:path*"] },
        { "group": "docs", "paths": ["/docs", "/docs/:path*"] }
      ],
      "development": { "local": 3001 }
    }
  },
  "options": {
    "localProxyPort": 3024
  }
}

Sheet 2 · Request

One decision, before any code runs.

Vercel's routing layer matches the path against the table in microfrontends.json and picks the project. It runs no application code, so neither app ever forwards a request to the other. The project that answers stamps x-mfe-zone on the response, so the result can be checked with curl.

1

Vercel routing picks the project

Reads the routing entries of microfrontends.json. /blog, /docs and every path under them belong to the blog, so the request goes straight to the blog project. Any other path has no entry and goes to the default app, the shell.

2

The project answers

The chosen project renders the page. Its proxy.ts decides nothing: it only sets x-mfe-zone: shell or x-mfe-zone: blog on the response. A path nobody has a page for gets the shell's 404.

Sheet 4 · Cheat sheet

Eight rules this repo follows.

Each rule is enforced in this repo by the contract tests in apps/shell/__tests__/routing.test.ts or was learned the hard way while deploying it (see EVIDENCE.md).

  1. One file, in the default app. microfrontends.json lives in apps/shell. Every application is keyed by its Vercel project name and carries its packageName; only the default app gets development.fallback and no routing block: it owns whatever nobody else claims.
  2. Children declare routing groups. Each child lists routing: [{ group, paths }]. Paths are path-to-regexp patterns, so list both the bare path and its wildcard: ["/blog", "/blog/:path*"], ["/docs", "/docs/:path*"].
  3. Routing happens before any code runs. Vercel matches the path and sends the request to one project. The shell never sees /blog or /docs, and no app forwards requests to the other. validateRouting checks every sample path.
  4. The shell's matcher must skip _next/, vc-ap- and child paths. The catch-all is /((?!_next/|vc-ap-|favicon.ico|blog/|blog$|docs/|docs$).*). Without the exclusions the shell proxy would shadow the blog's pages and its /vc-ap-5d190e/_next/… assets. blog/|blog$ rather than blog, so /blogroll would still reach the shell.
  5. Wrap next.config with withMicrofrontends. It reads the JSON, injects MFE_CONFIG, NEXT_PUBLIC_MFE_CURRENT_APPLICATION and the client's copy of the routing table at build time, and gives each child a hashed asset prefix vc-ap-<hash>.
  6. Link across zones with the microfrontends Link. Link from @vercel/microfrontends/next/client renders next/link inside a zone and a plain <a> (a full page load) into the other zone. PrefetchCrossZoneLinks in each layout lets the browser prefetch those pages.
  7. Hobby = one group of two projects. One microfrontends group per account, two projects per group, first two included for free. create-group must list the default app among --project too, or it answers "Default app must be one of the selected projects".
  8. Redeploy after create-group. Deployments built before the group existed ignore microfrontends.json: the shell answered 404 on /docs until both projects were redeployed once. Verify with curl -sI $HOST/docs | grep x-mfe-zone.

validateRouting

From @vercel/microfrontends/next/testing. Each sample path lands in the expected app: /, /does-not-exist, /lab.html in the shell; /blog, /blog/hello-world, /docs, /docs/getting-started in the blog. None of the blog's paths may fall through to the shell.

unstable_doesMiddlewareMatch

From next/experimental/testing/server. The shell proxy's matcher runs for the shell's paths and skips /blog, /docs, /vc-ap-… and /_next/…, but not /blogroll.
